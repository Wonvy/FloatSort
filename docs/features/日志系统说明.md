# FloatSort 日志系统说明

## 📋 系统架构

### 日志文件位置
- **文件夹**: `logs/`（统一使用这个文件夹）
- **文件格式**: `floatsort.YYYY-MM-DD.log`
- **示例**: `floatsort.2025-11-01.log`

### 日志写入方式

```
┌────────────────────────────────────────────────┐
│            Rust 后端 (tracing)                  │
│                                                │
│  info!("消息")  ──→  tracing_appender         │
│  warn!("警告")       ↓                         │
│  error!("错误")      ↓                         │
│                     ↓                          │
│              logs/floatsort.                   │
│              2025-11-01.log                    │
└────────────────────────────────────────────────┘

┌────────────────────────────────────────────────┐
│            前端 UI (JavaScript)                 │
│                                                │
│  addActivity("消息")  ──→  活动日志面板         │
│  (仅显示，不写入文件)                           │
└────────────────────────────────────────────────┘
```

## ✅ 已修复的问题

### 1. 日志文件后缀问题
**问题**: `tracing_appender` 自动添加 `.log` 后缀，但读取时没有加上
**修复**: 在 `read_log_by_date` 中添加 `.log` 后缀
```rust
let log_file = format!("logs/floatsort.{}.log", date);
```

### 2. "今天"按钮不加载日志
**问题**: 点击"今天"只清空UI，不加载日志文件
**修复**: 调用 `loadLogByDate(today)` 加载今天的日志
```javascript
async function showToday() {
    appState.currentLogDate = null;
    const today = formatDate(new Date());
    document.getElementById('logDatePicker').value = today;
    await loadLogByDate(today);
}
```

### 3. 旧日志系统冲突
**问题**: 存在两个日志系统（`log/` 和 `logs/` 文件夹）
**修复**: 
- 删除了 `activity_log.rs` 模块
- 统一使用 `tracing` 日志系统
- 清理了 `log/` 文件夹

## 🎯 日志功能

### 查看日志
1. **查看今天的日志**: 点击"📅 今天"按钮
2. **查看历史日志**: 
   - 点击日期选择器，选择具体日期
   - 点击 ◀ 查看上一天
   - 点击 ▶ 查看下一天
3. **打开日志文件夹**: 点击"📂 打开日志"

### 日志管理
1. **设置保留天数**: 应用设置 → 日志管理 → 选择天数
   - 7/15/30/60/90天
   - 永久保留（-1）
2. **自动清理**: 
   - 应用启动时自动清理过期日志
   - 修改设置后立即清理一次
3. **清空日志**: 点击"🗑️ 清空日志"（会显示清空数量）

## 📝 日志内容示例

### 日志文件格式

## 🔧 技术细节

### 日志解析
前端从日志文件读取内容时：
1. 提取时间戳：`2025-11-01T12:34:56`
2. 去掉日志级别：`INFO`/`WARN`/`ERROR`
3. 去掉模块前缀：`floatsort::file_monitor:`
4. 保留核心消息内容
5. 根据内容判断类型（成功/错误/信息）

### 保留天数处理
- `-1`: 永久保留，不清理
- `> 0`: 保留指定天数，自动清理过期日志
- 清理时机：应用启动 + 设置修改时

## 📌 注意事项

1. **前端活动日志**: 只在UI显示，不写入文件
2. **后端日志**: 自动写入 `logs/` 文件夹
3. **日志文件**: 每天一个文件，自动创建
4. **查看历史**: 可以查看任意历史日期的日志
5. **文件位置**: 应用根目录下的 `logs/` 文件夹
